# token-meter

Плагин показывает только фактический `thread/tokenUsage/updated`, полученный от BB:

- бейдж последнего realized assistant-сообщения хода: `↑вход ↓выход · cache N · M ток/с (эфф.)`; после ручного замера модели хода — ещё ` · модель ~K`;
- сводку контекста треда: `Σ N токенов · ~M ток/с (эфф.)` — сумма по записанным плагином ходам, не cumulative провайдера.

Не предлагай «исправить» отсутствие бейджа оценкой токенов. Сначала проверь провайдера: pi/codex отдают usage, command-code/gemini-web — нет. BB заменяет предыдущее usage-событие последним, поэтому история доступна только из записей, которые plugin успел накопить после установки.

`(эфф.)` — wall-clock `outputTokens / окно последнего вызова модели`, только при окне ≥1 с и output >0. Окно вызова: от завершения последнего инструмента хода до `turn/completed`; если инструментов не было — от `turn/started`. Сюда входит ожидание первого токена (обработка контекста, очередь, скрытое рассуждение). Это не provider-native tokens/sec и не чистая генерация; длительность всего хода и reasoning/cache read/write — в tooltip бейджа.

Чистую генерацию из событий bb вычесть нельзя: pi отдаёт сообщение bb целиком или крупными кусками, поэтому окно `agentMessage` — задержка доставки, а не печать токенов. Её даёт только кнопка **«Замерить»** в секции настроек плагина «Замер скорости модели». По умолчанию замер выключен. Включение: Settings → Installed plugins → Token meter — `benchEnabled`, `benchEndpoint` (OpenAI-совместимый base URL, например `http://localhost:8317/v1` или `https://example.com/v1`) и необязательный secret `benchApiKey`. Ключ не логируется и не возвращается в RPC. Замер — четыре non-stream запроса (`max_tokens` 150, 1500, 150, 1500), скорость по разнице средних длин и времени; одновременно разрешён один. Это 4 платных запроса, до ~3300 выходных токенов и до ~8 минут в худшем случае — предупреждай об этом до нажатия кнопки. Модель хода берётся из `client/turn/requested` этого хода, а не из дефолта треда.

Бейдж обновляется через теги RPC-кэша (`thread:<threadId>`), realtime-канал не используется. Бейдж виден в actionRow (у старых ответов — на hover); сообщения в свёрнутых группах timeline не монтируются, поэтому бейджа у них нет.

Retention: 500 ходов на тред и 30 дней. Нет сохранённой записи → UI должен возвращать `null`, без плейсхолдеров и выдуманных значений.

Проверки после изменений: `npm run typecheck`, `bb plugin build`, `npx vitest run` в `plugins/token-meter`.
