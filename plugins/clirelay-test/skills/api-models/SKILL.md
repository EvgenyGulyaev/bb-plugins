# Api модели (clirelay-test)

Панель bb «Api модели» управляет кастомными провайдерами pi в `~/.pi/agent/models.json`.

- Раскладка: три вкладки. «Аккаунты» — карточки квот аккаунтов relay (бары остатка с % и сбросом, бейджи план/провайдер/Success Rate/restriction), данные `GET {origin}/v0/management/ai-accounts/status`; доступ — логин/пароль админки relay в secret-настройках `managementUser`/`managementPassword` (плагин сам логинится и продлевает сессию). «Подключение» — аккордеон на API-адрес → слева доступные модели (`GET {baseUrl}/models`, минус подключённые), справа подключённые; аккордеон модели → форма настроек. Несколько провайдеров на одном адресе → вложенная группа адреса. «Значки моделей» — марки семейств и бейджи текущей модели у тредов (только pi).
- Конфиг: креды админки per-URL — кнопка «Креды» у группы адреса (диалог); глобальный fallback — `bb plugin config clirelay-test set managementUser <логин>` / `set managementPassword <пароль>` (+ reload); путь к файлу pi — `set modelsPath <путь>`, дефолт `~/.pi/agent/models.json`.
- RPC: `providers_list`, `provider_save`, `provider_delete`, `models_discover`, `model_connect`, `model_disconnect`, `model_update`, `model_toggle` (вкл/выкл: выключенные записи с настройками живут в kv `disabled-models:<providerId>`, pi видит только включённые), `model_test` (минимальный chat-запрос, латентность + ответ; только `openai-completions`, таймаут 30с), `relay_accounts` (квоты аккаунтов relay; без кредов → `configured:false`; `disabled`/`auth_name` мержатся из `GET /auth-files`, у shared-аккаунтов `disabled` из `health_status`), `relay_account_toggle` (вкл/выкл аккаунта: `PATCH /auth-files/status {name, disabled}`), `relay_creds_set` / `relay_creds_clear` (креды админки per-origin в server-side kv), `model_badges_state` (карта тредов + разрешённые марки), `model_badges_for {keys}` (keyed: бейдж или null на каждый threadId), `model_badges_marks_set` (сохранить марку семейства).
- Значки моделей: семейство по имени модели в нижнем регистре (`gpt`/`codex`, `claude`, `deepseek`, `grok`, `gemini`, `qwen`, `kimi`/`moonshot`, `llama`, `mistral`/`mixtral`; `x5`/`copilot-x5`/`x5-airun`/`copilot-*` → «х5»; иначе «Другие»). Список семейств — из `providers_list` + модели pi-тредов. Марка: BB-иконка, текст или inline SVG (валидация на сервере и клиенте: без script/foreignObject/img/use/style, `on*`, `javascript:`/`data:`, внешних href (в т.ч. unquoted) и `src`, ≤8000 символов); дефолты — разные иконки, у х5 текст «х5». kv `model-badges:marks`, realtime `model-badges-changed`.
- Бейджи: `experimental_threadRowMetadata` (марка у pi-треда, tooltip — id модели; виден только при включённых эксперименте `threadRowMetadata` и Organize → Rows → Metadata) и `experimental_threadContextSegment` (марка + имя модели в открытом треде). Модель треда: hook `message.dispatch` (`ctx.requestedExecution`) + ленивое `bb.sdk.threads.get`/`defaultExecutionOptions`; карта — kv `model-badges:threads`, `thread.archived`/`thread.deleted` чистят.
- UI: группировки по семейству модели в обеих колонках «Подключения»; фильтр Все/Вкл/Выкл; на «Аккаунтах» — сворачиваемые секции провайдеров, фильтры по состоянию и провайдеру, тумблеры аккаунтов; лейблы квот на русском (`lib/quota-labels.ts`); автозагрузка списков без ретраев после ошибки (`lib/auto-load.ts`).
- v1 поля модели: `name`, `reasoning`, `contextWindow`, `maxTokens`, `input`. Остальные поля файла сохраняются нетронутыми.
- pi подхватывает изменения при открытии `/model`.
- Секретность: ключи и адреса живут только в `models.json` вне репо, креды админки — в secret-настройках плагина, сессии — в server-side kv; не коммитить и не логировать их. `apiKey` фронтенду не возвращается.
- Ограничения: ключи `!command` не резолвятся для discovery; таргет только pi, бейджи/контекст — только у тредов `providerId === "pi"`; семейство нестандартного имени → «Другие».
- Тестовый шов: `PI_MODELS_PATH` переопределяет путь к файлу (используется в тестах).
