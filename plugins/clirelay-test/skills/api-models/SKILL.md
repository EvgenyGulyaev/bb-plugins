# Api модели (clirelay-test)

Панель bb «Api модели» управляет кастомными провайдерами pi в `~/.pi/agent/models.json`.

- Раскладка: две вкладки. «Аккаунты» — карточки квот аккаунтов relay (бары остатка с % и сбросом, `$` из `quota.used_cost_usd`, бейджи план/провайдер/Success Rate/restriction и чип `$… за 7 дн` из `usage.cost_total_7d`; title чипа: `cost_total`, `cycle_cost_total`, `request_total_7d`, при `cycle_known:false` цикл неизвестен). Если у квоты нет `reset_at`, но есть `window_seconds`: 100% → «окно не начато», <100% → «сброс неизвестен». У Claude 5 ч при нетронутом окне relay не сообщает `reset_at`; это не вычисленный локально сброс. Деньги форматирует `lib/money.ts`. Данные `GET {origin}/v0/management/ai-accounts/status`; доступ — логин/пароль админки relay в secret-настройках `managementUser`/`managementPassword` (плагин сам логинится и продлевает сессию). «Подключение» — аккордеон на API-адрес → слева доступные модели (`GET {baseUrl}/models`, минус подключённые), справа подключённые; аккордеон модели → форма настроек. Несколько провайдеров на одном адресе → вложенная группа адреса.
- Конфиг: креды админки per-URL — кнопка «Креды» у группы адреса (диалог); глобальный fallback — `bb plugin config clirelay-test set managementUser <логин>` / `set managementPassword <пароль>` (+ reload); путь к файлу pi — `set modelsPath <путь>`, дефолт `~/.pi/agent/models.json`.
- RPC: `providers_list`, `provider_save`, `provider_delete`, `models_discover` (старый контракт: `{models: string[]}`), `models_sync_scan`, `model_sync_apply`, `model_connect`, `model_disconnect`, `model_update` (патч API-полей; apiKey ""=очистить, headers мерж по ключам; ответ санитизирован — без apiKey/значений headers), `model_toggle` (вкл/выкл: выключенные записи с настройками живут в kv `disabled-models:<providerId>`, pi видит только включённые), `model_test` (минимальный chat-запрос, латентность + ответ; только `openai-completions`, таймаут 30с), `relay_accounts` (квоты аккаунтов relay; без кредов → `configured:false`; `disabled`/`auth_name` мержатся из `GET /auth-files`, у shared-аккаунтов `disabled` из `health_status`), `relay_account_toggle` (вкл/выкл аккаунта: `PATCH /auth-files/status {name, disabled}`), `relay_creds_set` / `relay_creds_clear` (креды админки per-origin в server-side kv).
- Кольца квот в рейле: галочка «Кольцо в рейле» на карточке аккаунта, в тулбаре «Аккаунтов» — ползунок «Размер колец» (24–64px, шаг 2) и «В строке» (1–4). KV `relay-rings` = `{ selected: string[], size: number, perRow: number }`, ключ аккаунта `${origin}|${auth_index}`; RPC `rings_state`, `rings_toggle {key,on}`, `rings_size {size}`, `rings_per_row {perRow}` (клампы 24..64 / 1..4, realtime `relay-rings-changed`). Кольца берут данные из `relay_accounts` (опрос раз в минуту при видимой вкладке, обновление по realtime). **Одно кольцо на тип провайдера** (kimi/claude/grok/gpt по маппингу логотипов, иначе id провайдера): percent = максимум остатка среди активных (disabled=false) аккаунтов типа, выключенные в максимум не входят, все выключены → «—»; подсказка «<тип>: осталось N% (больший активный из M)». Клик — попавер: список аккаунтов типа (активные первыми, затем по убыванию остатка, выключенные помечены) с их квотами, `$`, countdown до сброса или fallback без `reset_at` и строкой `$… за 7 дн`. Процент под кольцом виден всегда и ужимается вместе с ним (`clamp(7px, 26% размера кольца, 12px)`), поэтому 4 символа влезают даже в кольцо 18px; размер колец ужимается под ширину якоря рейла (`effectiveRingSize`). Логотипы kimi/claude/grok/gpt вендорены из lobe-icons (MIT) в `assets/` → `lib/provider-logos.ts`; неизвестный провайдер — первая буква имени. Якорь колец — content-script `relay-rings-anchor` в рейле bb (`lib/rings-rail.ts`), при смене разметки рейла кольца не рисуются, панель работает.
- UI: группировки по семейству модели в обеих колонках «Подключения»; фильтр Все/Вкл/Выкл; на «Аккаунтах» — сворачиваемые секции провайдеров, фильтры по состоянию и провайдеру, тумблеры аккаунтов; лейблы квот на русском (`lib/quota-labels.ts`); автозагрузка списков без ретраев после ошибки (`lib/auto-load.ts`).
- Поля модели: базовые `name`, `reasoning`, `contextWindow`, `maxTokens`, `input` + сворачиваемая секция «API-настройки»: `api`/`baseUrl` (override провайдера, пусто=наследовать), `apiKey` (write-only: пусто=не менять, «Очистить»=удалить), `headers` (write-only мерж по ключам на сервере, ""=удалить ключ, null=удалить всё; во view только имена), `thinkingLevelMap` (off/minimal/low/medium/high/xhigh/max, null=недоступен), `samplingParams`, `samplingParamsByThinkingLevel`, `compat` (loose-валидация частых полей + подсказка имён по api), `cost` (USD/1M, четыре обязательных + tiers), `promptCache` ({short,long} секунды), `inputLimits`. JSON-поля — textarea с zod-валидацией, пусто=удалить поле. Провайдер: `authHeader`, `oauth` (radius), `compat`, `headers` (та же семантика); `modelOverrides` не редактируется. Остальные поля файла сохраняются нетронутыми.
- Синхронизация новых моделей: `models_sync_scan {providerId}` → `{models: SyncModelView[]}` — только id, которых нет ни в `models`, ни в `disabled`, плюс metadata из whitelist API (`context_window`/`max_context_window`, `max_output_tokens`/`max_tokens`, `input_modalities`, `supported_reasoning_levels`) и детерминированный donor (`{id,name?,enabled,contextWindow?,maxTokens?,input?}`) либо `donorCandidates` без выбора. Ничего не пишет. `model_sync_apply {providerId, modelId, donorId, replaceInPi}` → `{status:applied|partial|noop, modelAdded, settings:skipped|updated|unchanged|failed, sources?}` — перечитывает `/models`, клонирует донора на сервере (apiKey/headers не уходят во фронт), пишет `models.json` атомарно; `replaceInPi:true` патчит соседний `settings.json` (preflight до записи models; exact `provider/model` в `enabledModels`, клон `compaction.modelOverrides` с сохранением donor override; `default*` не трогаются). Partial → warning и повтор с той же галочкой, второй клон не делается. Старая модель не отключается, pi не перезапускается.
- Донор: тот же provider, равные `(family, variant)` из id и только старшая версия; один максимум → автопредложение, tie/дубликат → ручной выбор, downgrade/нет пары/неверсионированный id → нет донора. Парсер и правила — `lib/model-sync.ts`.
- pi подхватывает изменения при открытии `/model`.
- Секретность: ключи и адреса живут только в `models.json` вне репо, креды админки — в secret-настройках плагина, сессии — в server-side kv; не коммитить и не логировать их. `apiKey` фронтенду не возвращается. Значения `headers` и `apiKey` моделей/провайдеров не возвращаются никогда (включая disabled-записи из kv и ответы `model_update`); во view только `apiKeySet`/`headersSet`/`headerNames`.
- Ограничения: ключи `!command` не резолвятся для discovery; таргет только pi.
- Тестовый шов: `PI_MODELS_PATH` переопределяет путь к файлу (используется в тестах).
