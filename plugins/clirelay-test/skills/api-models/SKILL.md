# Api модели (clirelay-test)

Панель bb «Api модели» управляет кастомными провайдерами pi в `~/.pi/agent/models.json`.

- Раскладка: три вкладки. «Аккаунты» — карточки квот аккаунтов relay (бары остатка с % и сбросом, `$` из `quota.used_cost_usd`, бейджи план/провайдер/Success Rate/restriction и чип `$… за 7 дн` из `usage.cost_total_7d`; title чипа: `cost_total`, `cycle_cost_total`, `request_total_7d`, при `cycle_known:false` цикл неизвестен). Если у квоты нет `reset_at`, но есть `window_seconds`: 100% → «окно не начато», <100% → «сброс неизвестен». У Claude 5 ч при нетронутом окне relay не сообщает `reset_at`; это не вычисленный локально сброс. Деньги форматирует `lib/money.ts`. Данные `GET {origin}/v0/management/ai-accounts/status`; доступ — логин/пароль админки relay в secret-настройках `managementUser`/`managementPassword` (плагин сам логинится и продлевает сессию). «Подключение» — аккордеон на API-адрес → слева доступные модели (`GET {baseUrl}/models`, минус подключённые), справа подключённые; аккордеон модели → форма настроек. Несколько провайдеров на одном адресе → вложенная группа адреса. «Настройки» — что показывать в строке треда и в бейдже (галочки полей, пример сразу меняется; не ждёт `providers_list`).
- Токены (бывший `token-meter`): бейдж у последнего ответа хода `↑вход ↓выход · cache N · M ток/с (эфф.)` и строка треда `Σ N токенов · ~M ток/с (эфф.)` — сумма по записанным плагином ходам, не cumulative провайдера. `(эфф.)` — wall-clock `outputTokens / окно последнего вызова модели` (от конца последнего инструмента хода или `turn/started` до `turn/completed`), только при окне ≥1 с и output >0; включает ожидание первого токена. Это не provider-native tokens/sec. Модель хода — из `client/turn/requested` этого хода, fallback — `defaultExecutionOptions`; `providerId` кэшируется на 60 с. Usage есть только у pi/codex: `command-code`/`gemini-web` его не отдают, и тогда UI возвращает `null`, без оценок и плейсхолдеров. Retention: 500 ходов на тред, 30 дней. Показ не влияет на сбор. Настройки — kv `tokens-display`, RPC `tokens_display_get/set`, тег `tokens-display`, изменения сразу во всех окнах; дефолт = прежний вид token-meter. История token-meter не переносится (другой kv): после переезда накопление с нуля, старый плагин надо удалить (`bb plugin uninstall token-meter`), иначе два бейджа.
- Конфиг: креды админки per-URL — кнопка «Креды» у группы адреса (диалог); глобальный fallback — `bb plugin config clirelay-test set managementUser <логин>` / `set managementPassword <пароль>` (+ reload); путь к файлу pi — `set modelsPath <путь>`, дефолт `~/.pi/agent/models.json`.
- RPC: `providers_list`, `provider_save`, `provider_delete`, `models_discover`, `model_connect`, `model_disconnect`, `model_update`, `model_toggle` (вкл/выкл: выключенные записи с настройками живут в kv `disabled-models:<providerId>`, pi видит только включённые), `model_test` (минимальный chat-запрос, латентность + ответ; только `openai-completions`, таймаут 30с), `relay_accounts` (квоты аккаунтов relay; без кредов → `configured:false`; `disabled`/`auth_name` мержатся из `GET /auth-files`, у shared-аккаунтов `disabled` из `health_status`), `relay_account_toggle` (вкл/выкл аккаунта: `PATCH /auth-files/status {name, disabled}`), `relay_creds_set` / `relay_creds_clear` (креды админки per-origin в server-side kv).
- Кольца квот в рейле: галочка «Кольцо в рейле» на карточке аккаунта, в тулбаре «Аккаунтов» — ползунок «Размер колец» (24–64px, шаг 2) и «В строке» (1–4). KV `relay-rings` = `{ selected: string[], size: number, perRow: number }`, ключ аккаунта `${origin}|${auth_index}`; RPC `rings_state`, `rings_toggle {key,on}`, `rings_size {size}`, `rings_per_row {perRow}` (клампы 24..64 / 1..4, realtime `relay-rings-changed`). Кольца берут данные из `relay_accounts` (опрос раз в минуту при видимой вкладке, обновление по realtime). **Одно кольцо на тип провайдера** (kimi/claude/grok/gpt по маппингу логотипов, иначе id провайдера): percent = максимум остатка среди активных (disabled=false) аккаунтов типа, выключенные в максимум не входят, все выключены → «—»; подсказка «<тип>: осталось N% (больший активный из M)». Клик — попавер: список аккаунтов типа (активные первыми, затем по убыванию остатка, выключенные помечены) с их квотами, `$`, countdown до сброса или fallback без `reset_at` и строкой `$… за 7 дн`. Процент под кольцом виден всегда и ужимается вместе с ним (`clamp(7px, 26% размера кольца, 12px)`), поэтому 4 символа влезают даже в кольцо 18px; размер колец ужимается под ширину якоря рейла (`effectiveRingSize`). Логотипы kimi/claude/grok/gpt вендорены из lobe-icons (MIT) в `assets/` → `lib/provider-logos.ts`; неизвестный провайдер — первая буква имени. Якорь колец — content-script `relay-rings-anchor` в рейле bb (`lib/rings-rail.ts`), при смене разметки рейла кольца не рисуются, панель работает.
- UI: группировки по семейству модели в обеих колонках «Подключения»; фильтр Все/Вкл/Выкл; на «Аккаунтах» — сворачиваемые секции провайдеров, фильтры по состоянию и провайдеру, тумблеры аккаунтов; лейблы квот на русском (`lib/quota-labels.ts`); автозагрузка списков без ретраев после ошибки (`lib/auto-load.ts`).
- v1 поля модели: `name`, `reasoning`, `contextWindow`, `maxTokens`, `input`. Остальные поля файла сохраняются нетронутыми.
- pi подхватывает изменения при открытии `/model`.
- Секретность: ключи и адреса живут только в `models.json` вне репо, креды админки — в secret-настройках плагина, сессии — в server-side kv; не коммитить и не логировать их. `apiKey` фронтенду не возвращается.
- Ограничения: ключи `!command` не резолвятся для discovery; таргет только pi.
- Тестовый шов: `PI_MODELS_PATH` переопределяет путь к файлу (используется в тестах).
