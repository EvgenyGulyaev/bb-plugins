# Rail Folders

Объединение иконок левого рейла BB в папки.

- Рейл целиком рисует плагин: Home, ваши папки и одиночные иконки в сохранённом порядке. Настройки BB по-прежнему рисует сам BB под колонкой.
- На рейле папка — только иконка: имя живёт в подсказке, доступном имени, шапке всплывающего списка и настройках.
- Клик по папке открывает список участников: иконка, название и бейдж. Клик по участнику открывает его в текущем окне, а с зажатым ⌘/Ctrl — в соседней панели (split), как и обычная иконка рейла.
- На папке появляется точка, если у любого её участника есть бейдж. Активная папка подсвечена, когда открыт один из её участников.
- Скрытые пользователем одиночные иконки остаются в меню «Ещё», а скрытые участники папки — внутри своей папки, поэтому ни одна иконка не пропадает.
- Пункт «Настроить рейл…» в меню «Ещё» открывает редактор плагина — модалку «Настроить рейл» с единым списком «Порядок рейла»: подсказка «Строки идут так же, как иконки на рейле; стрелки двигают строку», строки в точном порядке рейла (папки и одиночные иконки вперемешку, скрытые на своих слотах), у каждой строки номер позиции 1..N. Строка папки: иконка, имя, «Иконок: N», стрелки ↑/↓, «Переименовать» (тот же выбор иконки BB) и «Удалить» с подтверждением. Строка одиночной иконки: иконка, название, флажок «Видно» и стрелки ↑/↓; скрытые строки притушены, флажок снят. После клика стрелки список перерисовывается по ответу `rail_set_order` и номеру позиции: строка папки зримо переезжает между строками иконок, так что видно, где она окажется на рейле. Пустое состояние подсказывает создать папку правым кликом по иконке. В футере «Редактор BB…» открывает штатный редактор bb, «Готово» закрывает модалку. Меню «Ещё» доступно всегда, даже когда скрытых иконок нет.
- Правый клик по иконке: «Новая папка…», «Добавить в папку», «Убрать из папки», «Детали плагина». Правый клик по папке: переименовать или удалить.
- «Новая папка…» открывает модалку с сеткой иконок BB и полем имени (по умолчанию «Папка»). После OK папка создаётся пустой; иконки в неё добавляются перетаскиванием.
- Перетаскивание мышью: иконку рейла можно бросить на папку — она станет участником; строку участника можно перетащить внутри списка, чтобы поменять порядок, или вытащить на свободное место рейла — иконка вернётся в рейл. Папку можно бросить на другую папку или на одиночную иконку — линия вставки покажет, встанет ли она до или после цели по половине высоты, так папка занимает место между одиночными иконками. На свободное место рейла папка уходит в конец всей последовательности. Во время перетаскивания источник тускнеет, а цель подсвечивается линией вставки.
- Настройки → Папки рейла: создание папок, переименование, имя иконки BB, порядок папок стрелками по общей последовательности рейла (папка перешагивает и соседние папки, и одиночные иконки, а при старом порядке из одних папок стрелка сначала материализует весь рейл, поэтому папку можно опустить ниже одиночных иконок или в самый конец), порядок участников внутри каждой папки стрелками и удаление. Стрелки участников — клавиатурная и a11y-альтернатива перетаскиванию.
- Удаление папки не удаляет плагины и панели: её участники просто возвращаются в рейл по одной.
- Правый клик по строке проекта в сайдбаре добавляет в штатное меню bb пункт «Скопировать путь» — абсолютный путь чекаута проекта, как `pwd`. Если у проекта несколько окружений, вместо одного пункта появляется строка на каждый путь `<окружение>: <путь>` и «Скопировать все пути» (пути через перевод строки).
- Порядок сохраняется между запусками и синхронизируется между окнами сразу.

## Установка

```sh
bb plugin install git:https://github.com/EvgenyGulyaev/bb-plugins.git@main --plugin rail-folders
```

Из локального каталога:

```sh
bb plugin install ./plugins/rail-folders
```

После установки плагин один раз выбирает себя провайдером навигации. Дальше выбор запоминается в Настройках → Внешний вид → Навигация.

## Как это устроено

Состояние лежит в `bb.storage.kv` под ключом `rail-folders`:

```json
{
  "folders": [{ "id": "folder_ab12cd34ef56", "name": "Работа", "icon": "Briefcase", "itemIds": ["plugin-a/panel"] }],
  "order": ["__bb__/new-thread", "folder_ab12cd34ef56", "plugin-b/panel"]
}
```

`itemIds` участников — ключи навигации BB (`__bb__/new-thread`, `<pluginId>/<panelId>`). `order` — единый порядок рейла: id папок и якоря одиночных иконок вперемешку. Каждая папка встречается в нём ровно один раз. Иконка, которой нет в `order`, встаёт после якорных записей в порядке BB, а папка, забытая в `order`, — в самый конец (защита). Старое состояние, где `order` содержал только папки, читается как есть: одиночные иконки просто идут следом, внешний вид не меняется. Стрелка папки в этом случае материализует полную последовательность рейла и только потом двигает папку, поэтому первый же клик опускает её ниже одиночных иконок и сохраняет `order` смешанным. Иконка принадлежит не более чем одной папке. Испорченная запись не теряется целиком: невалидные папки отбрасываются при чтении, дубликаты схлопываются.

Все изменения идут через RPC (`server.ts`), после каждой записи публикуется сигнал `rail-folders-changed`, и открытые окна перечитывают состояние:

- `rail_state` — текущее состояние;
- `folders_create` — `{ name, icon, itemIds? }`;
- `folders_rename` — `{ id, name }`;
- `folders_set_icon` — `{ id, icon }`;
- `folders_delete` — `{ id }`;
- `folders_add_item` — `{ folderId, itemId }`;
- `folders_remove_item` — `{ itemId }`;
- `folders_reorder_items` — `{ id, itemIds }`: новый порядок участников; `itemIds` обязан быть перестановкой текущего состава папки, иначе RPC отклоняется;
- `rail_set_order` — `{ order }`: полная новая последовательность рейла (папки и якоря одиночных иконок). Дубликаты и пустые id отклоняет zod, потерю папки — сервер; неизменная последовательность не пишет kv. Этим RPC шлют результат стрелок папок и одиночных иконок: фронтенд знает список иконок BB, поэтому сам материализует последовательность;
- `project_paths` — `{ projectName }`: пути чекаутов проекта для пункта «Скопировать путь» (см. ниже);
- `folders_move` и `folders_reorder` оставлены для совместимости: сервер знает только те якоря одиночных иконок, что уже есть в `order`, поэтому эти RPC двигают папку внутри сохранённого порядка. Интерфейс плагина ими больше не пользуется.

Контракт описан zod-схемами в `server.ts` и общий для сервера и фронтенда. Чистая логика (нормализация, состав папок, порядок, раскладка рейла) — в `lib/folders.ts` без React и без обращений к BB.

## Редактор рейла

Модалка «Настроить рейл» — это поверхность плагина, поэтому папки и одиночные иконки видны в ней вместе, одним списком «Порядок рейла». Список строится из `railEditableSequence`: папки и одиночные иконки в том порядке, в котором их рисует рейл, скрытые иконки на своих якорных слотах, папки, которых нет в `order`, — в хвосте. Это превью, а не две статичные секции: стрелка шлёт `rail_set_order`, ответ RPC (или realtime-сигнал из другого окна) обновляет `state`, и строка перерисовывается на новом месте вместе со своим номером. Так видно, между какими иконками окажется папка, ещё до закрытия модалки.

Стрелки папки и стрелки одиночной иконки устроены одинаково: функция (`moveFolder` / `moveItemInOrder`) материализует полную последовательность рейла — папки, видимые и скрытые одиночные иконки, — и меняет местами два соседних слота, поэтому иконка или папка корректно перешагивает соседа любого типа. На старом порядке из одних папок материализация и есть то, что позволяет папке впервые встать между одиночными иконками или после них. Результат уходит одним `rail_set_order`; на краях последовательности, для неизвестного или сгруппированного id функция возвращает то же состояние, и запроса нет. Скрытая иконка остаётся в последовательности на своём якорном слоте, чтобы её можно было переставить, хотя на самом рейле её не видно.

Видимость иконок — не состояние плагина: флажок вызывает `actions.setVisible(itemId, visible)` из SDK, и bb сохраняет выбор в `sidebar.visiblePluginPanels`. В kv плагина видимость не пишется, новых RPC для неё нет. Футер модалки оставляет доступ к штатному редактору bb («Редактор BB…» → `actions.openCustomize()`).

## Перетаскивание и split

Иконка рейла — обёртка с `draggable` и полезной нагрузкой `text/rail-item-id`; сама кнопка внутри несёт `splitProps` от `experimental_useSidebarNavigationSplit`. Так обычный клик и ⌘-перетаскивание в соседнюю панель остаются на кнопке, а перетаскивание в папку — на обёртке. Строки участников в списке папки устроены так же, поэтому их можно вытащить наружу. Дополнительно строка принимает другую строку: линия сверху или снизу показывает, куда встанет участник, а `drop` отправляет полную перестановку `itemIds` в `folders_reorder_items`.

Папка тоже обёрнута в `draggable` с полезной нагрузкой `text/rail-folder-id`; кнопка при этом остаётся триггером popover и контекстного меню. Кнопка папки принимает иконку (`folders_add_item`), а кнопки папки и одиночной иконки принимают папку — вставка до/после по половине высоты с линией-индикатором на обоих типах целей. Для такого drop фронт материализует полную нарисованную последовательность id и отправляет её одним `rail_set_order`. Свободная область рейла принимает папку (в конец всей последовательности) или строку участника (`folders_remove_item`). Стрелки в настройках и в модалке делают то же самое без мыши, в том числе на старом порядке из одних папок: они материализуют последовательность и отправляют `rail_set_order`.

## Путь проекта в контекстном меню

Правый клик по строке проекта в сайдбаре открывает штатное меню bb («Настройки проекта», «Переименовать», «Hide from list», «Customize list», «Убрать»). Плагин не заменяет это меню и не перехватывает его события: content script `project-path-menu` (`app.contentScripts.register`) наблюдает за появлением меню проекта и добавляет в него свои пункты перед «Убрать».

- один чекаут — пункт «Скопировать путь»;
- несколько окружений — пункт на каждый путь `<окружение>: <путь>` (полный путь в `title`, длинный текст обрезается CSS) и «Скопировать все пути» — пути через `\n`;
- путей нет — меню остаётся ровно таким, каким его нарисовал bb.

Клик кладёт путь в буфер обмена (`navigator.clipboard.writeText`) и закрывает меню синтетическим `Escape`, который слушает Radix. Если браузер отказал в доступе к буферу, пункт меняется на «Не удалось скопировать» и меню остаётся открытым.

Меню проекта распознаётся по доступному имени `<имя проекта> actions` — оно приходит либо из `aria-label` меню, либо через `aria-labelledby` от кнопки-триггера «…» (так его размечает Radix) — и по наличию пункта «Project settings» (в русском интерфейсе — «Настройки проекта», его переводит русификатор). Дальше скрипт вызывает RPC:

```http
POST /api/v1/plugins/rail-folders/rpc/project_paths
{ "projectName": "bb-plugins" }
```

Ответ `{ items: [{ projectId, projectName, environmentName?, path, branchName? }] }`. Сервер берёт `bb.sdk.projects.list({ includePersonal: true })`, оставляет проекты с точно таким именем (регистр как есть; совпадений может быть несколько), для каждого читает `bb.sdk.environments.list({ projectId })`, пропускает окружения без `path`, опускает неизвестные `environmentName`/`branchName` (на границе RPC нет `undefined`) и дедуплицирует пути. Неизвестное имя проекта — `{ items: [] }`.

Пункты мышиные: Radix ведёт roving tabindex только по своим элементам, поэтому стрелки клавиатуры и Enter наши пункты не выбирают. Скрипт полностью fail-safe: любая ошибка внутри наблюдателя ловится и превращается в no-op, а при изменении разметки или подписей меню bb (например, в новой версии) пункты просто не появляются — само меню продолжает работать. Наблюдатель, слушатели и вставленные узлы удаляются в disposer'е контент-скрипта.

## Ограничения

- Плагин не добавляет свои команды CLI: раскладкой управляет пользователь в интерфейсе.
- Иконка папки задаётся именем иконки BB (например, `Folder`, `Briefcase`, `Terminal`) и не проверяется на существование: неизвестное имя показывается запасной иконкой. Модалка предлагает готовый набор имён, настройки принимают любое; уже сохранённое имя вне набора показывается в сетке первым и остаётся выбранным.
- Участники папки рисуются только внутри всплывающего списка; на самом рейле у папки одна иконка без подписи. Скрытые одиночные иконки доступны через «Ещё», скрытые участники — через свою папку.
- Иконки, которых больше нет (отключённый плагин или панель ещё загружается), остаются в `itemIds`, но не рисуются, пока BB не вернёт их в список навигации.
- Порядок участников внутри папки меняется перетаскиванием строк в popover или стрелками в настройках; порядок папок — перетаскиванием на рейле (на папку, одиночную иконку или свободное место) либо стрелками в настройках и в модалке «Настроить рейл»; порядок одиночных иконок — стрелками в модалке. Перетаскиванием сами одиночные иконки плагин не сортирует.
- Модалка «Настроить рейл» — единственное место, где папки и одиночные иконки видны вместе одним списком-превью; участники папки по-прежнему настраиваются в настройках плагина или в popover папки на рейле.
- Перетаскивание — нативное (HTML5 DnD), поэтому на сенсорных экранах без мыши оно недоступно; стрелки и флажки в модалке и настройках работают всегда.
- Пункты «Скопировать путь» в меню проекта — только для мыши (Radix не включает их в клавиатурный обход), и они зависят от текущей разметки меню bb: при её смене пункты просто перестают появляться, а меню bb остаётся рабочим.

## Откат навигации

Вернуть встроенный рейл:

```sh
bb settings ui set sidebar.navigationProvider navigation/rail
```

Или выбрать другой провайдер в Настройках → Внешний вид → Навигация, либо отключить плагин. Режим `__automatic__` выберет Rail Folders снова, пока плагин включён, поэтому для полного отказа укажите `navigation/rail` или отключите плагин.

## Разработка

```sh
npm install --include=dev
npm test
npm run typecheck
bb plugin build .
bb plugin reload rail-folders
```

Тесты: `lib/*.test.ts` — чистая модель (включая `moveItemInOrder`, `moveFolder` и `moveFolderToIndex` на старом и смешанном порядке), контракт `project_paths` и content script меню проекта (jsdom: вставка пунктов, клик, буфер, disposer), `server.test.ts` — RPC (в том числе `project_paths` на фейковом SDK) и установка на фейковом хосте BB, `test/app.test.tsx` — рейл, модалки (в том числе «Настроить рейл»), перетаскивание и настройки через `renderSlot`.

Четыре пакета в `devDependencies` — `better-sqlite3`, `@types/better-sqlite3`, `cron-parser` и `hono` — код плагина не импортирует. Их статически импортирует сам `@get-bb/plugin-sdk`: `better-sqlite3` и `hono` — в `bundled-types` (поэтому без них `tsc` с `skipLibCheck: false` падает на объявлениях SDK), все три, включая `cron-parser`, — в `dist/testing`, который загружает `server.test.ts`. Удалять их нельзя: без них не проходят `npm run typecheck` и серверные тесты.
