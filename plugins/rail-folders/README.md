# Rail Folders

Объединение иконок левого рейла BB в папки.

- Рейл целиком рисует плагин: Home, ваши папки и одиночные иконки в сохранённом порядке. Настройки BB по-прежнему рисует сам BB под колонкой.
- На рейле папка — только иконка: имя живёт в подсказке, доступном имени, шапке всплывающего списка и настройках.
- Клик по папке открывает список участников: иконка, название и бейдж. Клик по участнику открывает его в текущем окне, а с зажатым ⌘/Ctrl — в соседней панели (split), как и обычная иконка рейла.
- На папке появляется точка, если у любого её участника есть бейдж. Активная папка подсвечена, когда открыт один из её участников.
- Скрытые пользователем одиночные иконки остаются в меню «Ещё», а скрытые участники папки — внутри своей папки, поэтому ни одна иконка не пропадает.
- Пункт «Настроить рейл…» в меню «Ещё» открывает встроенный редактор BB: скрытие и порядок одиночных иконок. Меню доступно всегда, даже когда скрытых иконок нет.
- Правый клик по иконке: «Новая папка…», «Добавить в папку», «Убрать из папки», «Детали плагина». Правый клик по папке: переименовать или удалить.
- «Новая папка…» открывает модалку с сеткой иконок BB и полем имени (по умолчанию «Папка»). После OK папка создаётся пустой; иконки в неё добавляются перетаскиванием.
- Перетаскивание мышью: иконку рейла можно бросить на папку — она станет участником; строку участника можно перетащить внутри списка, чтобы поменять порядок, или вытащить на свободное место рейла — иконка вернётся в рейл. Папку можно бросить на другую папку (до или после неё по половине высоты) либо на свободное место рейла — она встанет в конец порядка папок. Во время перетаскивания источник тускнеет, а цель подсвечивается линией вставки.
- Настройки → Папки рейла: создание папок, переименование, имя иконки BB, порядок папок стрелками, порядок участников внутри каждой папки стрелками и удаление. Стрелки участников — клавиатурная и a11y-альтернатива перетаскиванию.
- Удаление папки не удаляет плагины и панели: её участники просто возвращаются в рейл по одной.
- Порядок сохраняется между запусками и синхронизируется между окнами сразу.

## Установка

```sh
bb plugin install git:https://github.com/EvgenyGulyaev/bb-plugins.git@main --plugin rail-folders
```

Из локального каталога:

```sh
bb plugin install ./plugins/rail-folders
```

После установки плагин один раз выбирает себя провайдером навигации. Дальше выбор запоминается в Настройках → Внешний вид → Навигация.

## Как это устроено

Состояние лежит в `bb.storage.kv` под ключом `rail-folders`:

```json
{
  "folders": [{ "id": "folder_ab12cd34ef56", "name": "Работа", "icon": "Briefcase", "itemIds": ["plugin-a/panel"] }],
  "order": ["__bb__/new-thread", "folder_ab12cd34ef56", "plugin-b/panel"]
}
```

`itemIds` участников — ключи навигации BB (`__bb__/new-thread`, `<pluginId>/<panelId>`). `order` задаёт позиции папок и одиночных иконок; иконка, которой нет в `order`, встаёт на своё место по порядку BB. Иконка принадлежит не более чем одной папке. Испорченная запись не теряется целиком: невалидные папки отбрасываются при чтении, дубликаты схлопываются.

Все изменения идут через RPC (`server.ts`), после каждой записи публикуется сигнал `rail-folders-changed`, и открытые окна перечитывают состояние:

- `rail_state` — текущее состояние;
- `folders_create` — `{ name, icon, itemIds? }`;
- `folders_rename` — `{ id, name }`;
- `folders_set_icon` — `{ id, icon }`;
- `folders_delete` — `{ id }`;
- `folders_add_item` — `{ folderId, itemId }`;
- `folders_remove_item` — `{ itemId }`;
- `folders_move` — `{ id, direction: "up" | "down" }`;
- `folders_reorder_items` — `{ id, itemIds }`: новый порядок участников; `itemIds` обязан быть перестановкой текущего состава папки, иначе RPC отклоняется;
- `folders_reorder` — `{ id, index }`: новая позиция папки среди папок; индекс клампится к `0..count-1`, неизменная позиция не пишет kv.

Контракт описан zod-схемами в `server.ts` и общий для сервера и фронтенда. Чистая логика (нормализация, состав папок, порядок, раскладка рейла) — в `lib/folders.ts` без React и без обращений к BB.

## Перетаскивание и split

Иконка рейла — обёртка с `draggable` и полезной нагрузкой `text/rail-item-id`; сама кнопка внутри несёт `splitProps` от `experimental_useSidebarNavigationSplit`. Так обычный клик и ⌘-перетаскивание в соседнюю панель остаются на кнопке, а перетаскивание в папку — на обёртке. Строки участников в списке папки устроены так же, поэтому их можно вытащить наружу. Дополнительно строка принимает другую строку: линия сверху или снизу показывает, куда встанет участник, а `drop` отправляет полную перестановку `itemIds` в `folders_reorder_items`.

Папка тоже обёрнута в `draggable` с полезной нагрузкой `text/rail-folder-id`; кнопка при этом остаётся триггером popover и контекстного меню. Кнопка папки принимает иконку (`folders_add_item`) и другую папку (`folders_reorder`, вставка до/после по половине высоты), а свободная область рейла — папку (в конец порядка) или строку участника (`folders_remove_item`). Стрелки в настройках делают то же самое без мыши.

## Ограничения

- Плагин не добавляет свои команды CLI: раскладкой управляет пользователь в интерфейсе.
- Иконка папки задаётся именем иконки BB (например, `Folder`, `Briefcase`, `Terminal`) и не проверяется на существование: неизвестное имя показывается запасной иконкой. Модалка предлагает готовый набор имён, настройки принимают любое; уже сохранённое имя вне набора показывается в сетке первым и остаётся выбранным.
- Участники папки рисуются только внутри всплывающего списка; на самом рейле у папки одна иконка без подписи. Скрытые одиночные иконки доступны через «Ещё», скрытые участники — через свою папку.
- Иконки, которых больше нет (отключённый плагин или панель ещё загружается), остаются в `itemIds`, но не рисуются, пока BB не вернёт их в список навигации.
- Порядок участников внутри папки меняется перетаскиванием строк в popover или стрелками в настройках; порядок папок — перетаскиванием на рейле или стрелками в настройках.
- Перетаскивание — нативное (HTML5 DnD), поэтому на сенсорных экранах без мыши оно недоступно; стрелки в настройках и добавление через контекстное меню работают всегда.

## Откат навигации

Вернуть встроенный рейл:

```sh
bb settings ui set sidebar.navigationProvider navigation/rail
```

Или выбрать другой провайдер в Настройках → Внешний вид → Навигация, либо отключить плагин. Режим `__automatic__` выберет Rail Folders снова, пока плагин включён, поэтому для полного отказа укажите `navigation/rail` или отключите плагин.

## Разработка

```sh
npm install --include=dev
npm test
npm run typecheck
bb plugin build .
bb plugin reload rail-folders
```

Тесты: `lib/*.test.ts` — чистая модель, `server.test.ts` — RPC и установка на фейковом хосте BB, `test/app.test.tsx` — рейл, модалки, перетаскивание и настройки через `renderSlot`.

Четыре пакета в `devDependencies` — `better-sqlite3`, `@types/better-sqlite3`, `cron-parser` и `hono` — код плагина не импортирует. Их статически импортирует сам `@get-bb/plugin-sdk`: `better-sqlite3` и `hono` — в `bundled-types` (поэтому без них `tsc` с `skipLibCheck: false` падает на объявлениях SDK), все три, включая `cron-parser`, — в `dist/testing`, который загружает `server.test.ts`. Удалять их нельзя: без них не проходят `npm run typecheck` и серверные тесты.
