---
name: rail-folders
description: Иконки левого рейла BB, объединённые в папки; управление составом и порядком.
---

Rail Folders рисует левый рейл BB и позволяет складывать иконки в папки. На рейле папка — только иконка: имя видно в подсказке, доступном имени, шапке всплывающего списка и настройках. Клик по папке раскрывает участников, клик по участнику открывает панель (⌘/Ctrl — соседняя панель). Правый клик по иконке: «Новая папка…», «Добавить в папку», «Убрать из папки»; правый клик по папке: переименовать или удалить. «Новая папка…» открывает модалку с сеткой иконок BB и полем имени (по умолчанию «Папка») — после OK папка создаётся пустой. Переименование использует тот же выбор иконки.

Иконку можно перетащить мышью на папку — она станет участником; строку участника можно перетащить внутри списка, чтобы поменять порядок, или вытащить на свободное место рейла — иконка вернётся в рейл. Папку можно перетащить на другую папку или на одиночную иконку — линия вставки покажет, встанет ли она до или после цели по половине высоты, поэтому папка встаёт между одиночными иконками. На свободное место рейла папка уходит в конец. Скрытые одиночные иконки остаются в «Ещё», скрытые участники — внутри своей папки. Пункт «Настроить рейл…» в меню «Ещё» открывает редактор плагина — модалку «Настроить рейл» с одним списком «Порядок рейла»: строки идут ровно в порядке рейла (`railEditableSequence`: папки и одиночные иконки вперемешку, скрытые на своих слотах, забытые папки в хвосте), у каждой строки позиционный номер 1..N. Строка папки — иконка, имя, «Иконок: N», стрелки ↑/↓, «Переименовать» с выбором иконки BB и «Удалить» с подтверждением; строка одиночной иконки — иконка, название, чекбокс «Видно» и стрелки ↑/↓, скрытые притушены и со снятым флажком. Стрелка шлёт `rail_set_order`, состояние возвращается из RPC, и список перерисовывается в новом порядке — строка папки зримо переезжает между строками иконок, это живой превью рейла. Футер: «Редактор BB…» — штатный редактор bb, «Готово» — закрыть. Настройки → Папки рейла создают папки, меняют имя иконки BB, порядок папок стрелками по общей последовательности рейла (папка перешагивает и соседние папки, и одиночные иконки) и порядок участников внутри каждой папки стрелками — это клавиатурная и a11y-альтернатива перетаскиванию.

Состояние хранится в kv-ключе `rail-folders`:

```json
{ "folders": [{ "id": "folder_ab12cd34ef56", "name": "Работа", "icon": "Briefcase", "itemIds": ["plugin-a/panel"] }], "order": ["__bb__/new-thread", "folder_ab12cd34ef56", "plugin-b/panel"] }
```

`order` — единый порядок рейла: id папок и якоря одиночных иконок вперемешку, каждая папка ровно один раз. Иконка без записи в `order` встаёт после якорных записей в порядке BB, папка без записи — в самый конец (защита). Старое состояние, где `order` содержал только папки, читается как есть: одиночные иконки идут следом, внешний вид не меняется. Папку можно поставить в любое место рейла — в начало, между одиночными иконками и в конец — и перетаскиванием, и стрелками; на старом порядке стрелка сначала материализует полную последовательность рейла, поэтому первый клик уже опускает папку ниже одиночных иконок.

Меняется только через RPC плагина: `rail_state`, `folders_create`, `folders_rename`, `folders_set_icon`, `folders_delete`, `folders_add_item`, `folders_remove_item`, `folders_reorder_items` (`{ id, itemIds }`, перестановка текущего состава), `rail_set_order` (`{ order }`, полная новая последовательность; дубликаты и пустые id отклоняет zod, потерю папки — сервер). `folders_move` (`{ id, direction }`) и `folders_reorder` (`{ id, index }`) остались для совместимости: сервер знает только якоря, уже записанные в `order`, поэтому интерфейс плагина ими больше не пользуется. После записи публикуется `rail-folders-changed`; открытые окна перечитывают состояние. Иконка принадлежит не более чем одной папке; удаление папки возвращает участников в рейл.

Стрелки папки и одиночной иконки в модалке и в настройках материализуют полную последовательность рейла и отправляют один `rail_set_order`; в kv порядок попадает только так. Модалка перерисовывает единый список по ответу RPC (и по realtime `rail-folders-changed` из другого окна), поэтому папка после клика видна на новом месте и её номер меняется. Видимость иконок — не состояние плагина: флажок вызывает `actions.setVisible(itemId, visible)`, bb сам хранит это в `sidebar.visiblePluginPanels`. Новых RPC для модалки нет.

Ограничения: CLI-команд у плагина нет; имя иконки не проверяется (неизвестное показывается запасной иконкой); участники папки видны только во всплывающем списке, их порядок меняется в настройках плагина или перетаскиванием в popover; пропавшие из навигации BB иконки сохраняются в составе, но не рисуются; перетаскивание нативное (HTML5 DnD) и требует мыши, порядок и видимость без мыши меняются в модалке «Настроить рейл».

Правый клик по проекту в сайдбаре: content script `project-path-menu` дописывает в штатное меню bb (само меню не заменяется) пункт «Скопировать путь» — абсолютный путь чекаута. Если у проекта несколько окружений, появляется строка на каждый путь `<окружение>: <путь>` и «Скопировать все пути» (через `\n`); если путей нет, меню не меняется. Клик пишет путь в буфер и закрывает меню синтетическим Escape; при отказе буфера пункт становится «Не удалось скопировать». Пути отдаёт RPC `project_paths` (`{ projectName }` → `{ items: [{ projectId, projectName, environmentName?, path, branchName? }] }`): проекты ищутся по точному имени через `bb.sdk.projects.list({ includePersonal: true })`, окружения — через `bb.sdk.environments.list({ projectId })`, пути дедуплицируются. Ограничения: пункты только мышиные (Radix не берёт их в клавиатурный обход) и зависят от разметки меню bb — при её смене пункты перестают появляться, а меню bb продолжает работать (ошибки наблюдателя глушатся).

Не переключай провайдер навигации и не меняй раскладку без явной просьбы пользователя. Откат на встроенный рейл: `bb settings ui set sidebar.navigationProvider navigation/rail`. Режим `__automatic__` выберет этот плагин снова, пока он включён.
